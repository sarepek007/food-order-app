# Структура проекта

Правило одно: **зависимости направлены внутрь**. Транспорт знает про сценарии,
сценарии знают про домен, домен не знает ни про кого. Нарушение этого правила
видно по импорту — если в файле домена появился `fastify` или `drizzle`,
что-то пошло не так.

```
food-order-app/
├── packages/contracts/     общий контракт: домен и форма обмена
├── apps/api/               REST API, миграции, seed
├── apps/web/               интерфейс оператора
├── e2e/                    сценарии в браузере
├── docs/                   спецификация, план, решения
├── infra/                  инициализация Postgres
└── .github/workflows/      CI
```

---

## `packages/contracts` — общий контракт

Единственное место, где объявлены статусы, правила и формы данных.
Импортируется и сервером, и клиентом: рассинхрон невозможен по построению.

```
src/
├── domain/                 правила и словарь предметной области
│   ├── order-status.ts     граф переходов данными, предикаты статусов
│   ├── order-rules.ts      чистые проверки: переход, отмена, лимит курьера
│   ├── sla.ts              нормативы времени на статус, признак просрочки
│   ├── audit.ts            типы событий журнала
│   ├── search.ts           нормализация адреса (зеркало SQL-функции)
│   └── error-codes.ts      коды ошибок как словарь домена
├── api/                    то, что уходит по проводу
│   ├── problem.ts          RFC 9457 и отображение кодов в HTTP-статусы
│   ├── schemas.ts          Zod-схемы запросов и ответов, из них же OpenAPI
│   ├── idempotency.ts      протокол повторяемых запросов
│   └── order-events.ts     событие изменения заказа
└── index.ts                barrel: наружу пакет плоский
```

`api/` зависит от `domain/`, но не наоборот. Поэтому коды ошибок лежат
в домене, а их отображение в HTTP-статусы — в транспорте: доменный слой
не должен знать протокол, по которому его случилось выставить наружу.

## `apps/api` — сервер

```
migrations/                 SQL-миграции, источник правды о схеме
scripts/                    разовые задачи: нагрузочный прогон, база для e2e
src/
├── main.ts                 точка входа: миграции, подписка, запуск, остановка
├── app.ts                  сборка Fastify: плагины, маршруты, OpenAPI
├── config.ts               конфигурация из env, Zod-валидация при старте
├── routes/                 разбор запроса → вызов сценария → ETag
├── plugins/                обработчик ошибок, автор действия
├── http/                   problem+json, предусловия If-Match, идемпотентность
├── services/               сценарии: транзакции, блокировки, журнал
├── repositories/           единственное место, где известно про SQL
├── realtime/               подписка на LISTEN/NOTIFY
├── db/                     пул, схема drizzle, раннер миграций
├── errors/                 DomainError
└── seed/                   генератор воспроизводимых данных
tests/
├── db/  services/  http/  realtime/  seed/    зеркалят структуру src
└── helpers/                пул, приложение, сервис для тестов
```

Поток запроса: `routes` → `services` → `repositories` → Postgres.
Бизнес-правила берутся из `@food/contracts` и не дублируются.

## `apps/web` — интерфейс

```
src/
├── main.tsx                монтирование, провайдеры
├── app/                    оболочка: маршруты, шапка, граница ошибок, кэш
├── api/                    клиент, ошибки, хуки запросов, поток изменений
├── features/orders/        возможность целиком
│   ├── filters.ts          состояние выборки ⇄ адресная строка
│   ├── pages/              страницы: список и карточка
│   └── components/         части этих страниц
├── components/             общие элементы: кнопка, бейдж, модалка, состояния
├── lib/                    форматирование, ограничитель частоты
└── test/                   MSW, фикстуры, рендер с провайдерами
```

Деление `pages/` и `components/` появилось не сразу: четырнадцать файлов
в одной папке перестали читаться. Страница отвечает за состояние и запросы,
компонент — только за отображение переданного.

## Куда класть новое

| Что добавляете | Куда |
|----------------|------|
| Правило предметной области | `contracts/src/domain/` + тест рядом |
| Поле в ответе API | `contracts/src/api/schemas.ts`, затем маппер в `api/src/services/` |
| Новый эндпоинт | `api/src/routes/`, логика — в `services/` |
| Запрос к базе | `api/src/repositories/`, схема — миграцией |
| Экран | `web/src/features/<возможность>/pages/` |
| Элемент, нужный двум возможностям | `web/src/components/` |
