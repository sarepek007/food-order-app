# ADR 0004. Версию и updated_at ведёт триггер БД

**Статус:** принято · M2

## Контекст

Оптимистическая блокировка требует счётчика, который невозможно обойти.
Если версию инкрементирует приложение, любой забытый `SET version = version + 1`
(в миграции данных, в seed, в новом эндпоинте) создаёт дыру: конкурентное
изменение перестаёт обнаруживаться.

## Решение

Триггер `BEFORE UPDATE ON orders`:

```sql
IF (to_jsonb(NEW) - ignored) IS DISTINCT FROM (to_jsonb(OLD) - ignored) THEN
    NEW.version := OLD.version + 1;
    NEW.updated_at := now();
END IF;
```

Из сравнения исключены `version`, `updated_at` и `delivery_address_normalized`.
Приложение выполняет `UPDATE ... WHERE id = $1 AND version = $2` и по `rowCount = 0`
понимает, что его версия устарела.

## Следствия

* Версию нельзя подделать из приложения: явный `SET version = 100` перетирается
  триггером (закрыто тестом).
* Холостой `UPDATE` версию не двигает — оператор не получает ложный конфликт
  из-за сохранения без изменений.
* Плата: `to_jsonb` на каждое обновление строки. Для операционной консоли
  с десятками обновлений в секунду это несопоставимо дешевле, чем цена ошибки.

## Найдено при реализации

Первая версия использовала `NEW IS DISTINCT FROM OLD` и **всегда** считала строку
изменённой: в `BEFORE`-триггере STORED-генерируемая колонка ещё не вычислена,
в `NEW` она `NULL`, в `OLD` — значение. Дефект поймал тест на холостой `UPDATE`.
