# ADR 0003. Рукописные SQL-миграции + Drizzle как построитель запросов

**Статус:** принято · M2

## Контекст

Схеме нужны вещи, которые ORM-генераторы либо не умеют, либо прячут:
частичный индекс по активным заказам курьера, GIN-индекс по триграммам,
генерируемая колонка, триггер версионирования и триггер, запрещающий правку журнала.
Одновременно прикладному коду нужны типизированные запросы с восемью
опциональными фильтрами.

## Решение

* **Миграции — рукописный SQL** в `apps/api/migrations/*.sql`, применяются
  собственным раннером (`src/db/migrate.ts`): порядок по имени файла,
  каждая в своей транзакции, отметка в `schema_migrations`, контрольная сумма
  против правки уже применённых файлов, advisory-лок против параллельного старта реплик.
* **Drizzle** используется только как типизированный построитель запросов
  поверх существующей схемы (`src/db/schema.ts`), без `drizzle-kit generate`.
* Расхождение зеркала и реальной схемы ловит тест `drizzle-schema.test.ts`:
  он сверяет колонки каждой таблицы с `information_schema`.

## Следствия

* Полный контроль над DDL: триггеры и частичные индексы описаны явно и читаемо.
* Плата — ручная синхронизация `schema.ts`; закрыта тестом.
* Раннер тестируется как обычный код: идемпотентность, откат битой миграции,
  защита от изменения применённого файла, параллельный запуск.

## Найдено при реализации

* `CREATE TABLE IF NOT EXISTS` в Postgres **не атомарен**: два параллельных
  раннера падали на `duplicate key ... pg_type_typname_nsp_index`.
  Создание служебной таблицы перенесено под advisory-лок.
* `gin_trgm_ops` не резолвится, если схема с расширением отсутствует в `search_path` —
  учтено в тестовой изоляции по схемам.
