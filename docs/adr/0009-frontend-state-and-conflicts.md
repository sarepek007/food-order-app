# ADR 0009. Состояние фронтенда: URL, кэш и разбор конфликтов

**Статус:** принято · M6

## Контекст

Операционной консоли нужны три вещи, которые обычно делают плохо:
воспроизводимая выборка, честные состояния загрузки и понятная реакция
на чужие изменения.

## Решения

### Фильтры живут в адресной строке

Единственный источник правды о выборке — query string. Компонент читает
`useSearchParams`, а не хранит состояние у себя. Следствия: ссылку на выборку
можно переслать коллеге, F5 ничего не теряет, кнопка «назад» работает
ожидаемо. В URL пишутся только отличия от значений по умолчанию, поэтому
адрес остаётся читаемым.

Любое изменение фильтра сбрасывает страницу на первую — иначе оператор
попадает на пустую страницу 7 в выборке из двух записей.

### Действия над заказом не дублируют доменные правила

Кнопки переходов строятся по `allowedTransitions` из ответа сервера и
`nextProgressStatuses()` из `@food/contracts` — того же графа, по которому
сервер валидирует запрос. Недопустимое действие **не показывается**, а не
показывается неактивным без объяснения. Рассинхрон невозможен по построению.

Загрузка курьера (`2/3`) видна в диалоге до нажатия: переполненный курьер
заблокирован с подсказкой. Сервер всё равно проверит лимит — интерфейс лишь
экономит заведомо неудачную попытку.

### Конфликт версий — отдельное состояние интерфейса, а не тост

Ошибка `409 ORDER_VERSION_CONFLICT` не показывается как обычная ошибка.
Она разворачивается в баннер, который сообщает:

* обе версии — свою и актуальную;
* **что именно изменилось** — списком из журнала («курьер Ольга Лебедева → Алексей Новиков»);
* какое действие оператора не применилось.

И даёт выбор: посмотреть актуальный заказ либо применить своё изменение
поверх. Второе отправляет `If-Match: *` — то самое «применить поверх текущего
состояния» из [ADR 0007](0007-http-semantics.md). Форма при этом не сбрасывается,
а старое значение не уходит на сервер повторно само по себе.

### Ошибки разложены по типам

| Тип | Как показывается |
|-----|------------------|
| сеть недоступна | «Нет связи с сервером. Проверьте подключение к сети» + «Повторить» |
| сервис не отвечает | «Сервис временно недоступен (502). Изменения не сохранены» + «Повторить» |
| 4xx/5xx | сообщение сервера из `problem+json` + «Повторить» |
| `VALIDATION_FAILED` | по полям формы, через `details.issues[].path` |
| бизнес-ошибка (409/422) | баннер с текстом сервера, форма не теряет ввод |
| конфликт версий | отдельный баннер с разбором |
| успех | тост + инвалидация кэша заказа, журнала и справочника курьеров |

Компоненты ветвятся по `code`, а не по тексту сообщения.

### Кэш

`placeholderData` при пагинации: таблица не мигает при переходе между
страницами. Справочник ресторанов живёт 5 минут, справочник курьеров — 15 секунд,
потому что его загрузка меняется вместе с заказами. После мутации свежий заказ
кладётся в кэш напрямую, поэтому карточка не показывает лоадер повторно.

## Тестирование

Сеть перехватывается на уровне HTTP (MSW), а не подменой модулей: тесты
проходят через настоящий `fetch` и настоящий разбор `problem+json`.
Поэтому один и тот же тест проверяет и компонент, и клиент API.

### Недоступный сервис — не ошибка запроса

Ответ `5xx` **без** `problem+json` приходит не от приложения, а от прокси
перед ним: Vite отдаёт пустой `500 text/plain`, nginx — HTML-страницу `502`.
Разбирать такое тело как ошибку API бессмысленно: клиент показывал бы
«Сервер вернул 500 без пояснения» — код состояния вместо объяснения.

Такой ответ распознаётся отдельно и превращается в сообщение, которое говорит
оператору три нужные вещи: что случилось, что изменения **не сохранены**
и что делать дальше. Код состояния остаётся в скобках — для поддержки.

Граница проверена тестами с обеих сторон: `5xx` **с** `problem+json`
по-прежнему считается ошибкой приложения и показывает её текст.

## Найдено при реализации

Тест на отмену заказа поймал дефект доступности: сообщение об ошибке лежало
**внутри** `<label>` и попадало в доступное имя поля — скринридер читал
«Причина отмены Укажите причину отмены». Сообщение вынесено из подписи
и связано через `aria-describedby`.
