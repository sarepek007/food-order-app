# ADR 0001. Общий пакет контрактов вместо дублирования правил

**Статус:** принято · M1

## Контекст

Граф статусов и правила отмены нужны в трёх местах: валидация на сервере,
рендер доступных действий в UI и генерация тестовых данных в seed. Классический
путь — продублировать список статусов строками на фронте — приводит к расхождению
при первом же изменении жизненного цикла.

## Решение

Домен вынесен в `packages/contracts`:

* статусы, граф переходов и предикаты — данными, а не условиями;
* правила — чистыми функциями `check*`, возвращающими `RuleResult`
  (`{ ok: true }` либо код + человекочитаемое сообщение + детали);
* Zod-схемы запросов/ответов — там же, из них выводятся типы и OpenAPI.

Пакет не зависит ни от Postgres, ни от Fastify, ни от React.

## Следствия

* UI не показывает кнопку недопустимого перехода, потому что читает тот же граф,
  что и сервер, — рассинхрон невозможен по построению.
* Правила тестируются юнит-тестами без БД: 118 тестов исполняются за 0.3 с.
* Текст ошибки формируется в домене, поэтому сообщение в UI и в API идентично.
* Плата: сборка `contracts` обязана предшествовать сборке приложений
  (`tsc -b` project references).

## Альтернативы

* **Дублировать правила на фронте** — отклонено: гарантированный рассинхрон.
* **Генерировать типы из OpenAPI** — оставлено как дополнение; типы описывают
  форму данных, но не переносят поведение (граф переходов, предикаты).
