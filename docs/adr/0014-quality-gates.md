# ADR 0014. Проверки качества: пороги покрытия, доступность, нагрузка

**Статус:** принято · M14

## Контекст

Три дыры в самой системе проверок:

* покрытие измерялось, но ничем не удерживалось — регрессия прошла бы незаметно;
* дефект доступности (сообщение об ошибке внутри `<label>`, из-за которого
  скринридер читал подпись поля вместе с текстом ошибки) нашёлся **случайно**,
  когда упал компонентный тест;
* лимит курьера проверялся на пяти параллельных запросах — этого мало,
  чтобы говорить о поведении под нагрузкой.

## Решения

### Пороги покрытия — защита от регрессии, а не гонка за процентами

Пороги выставлены на несколько пунктов **ниже достигнутого** и заданы
в конфигурации каждого пакета. Смысл — «не хуже, чем сейчас»; поднимаются
осознанно, когда покрытие выросло.

| Пакет | Строки | Ветви | Функции |
|-------|--------|-------|---------|
| `contracts` | 91% при пороге 88 | 95% / 90 | 97% / 92 |
| `api` | 94% / 90 | 90% / 85 | 91% / 88 |
| `web` | 91% / 88 | 85% / 80 | 88% / 85 |

Первый прогон показал, что у `app/` (граница ошибок, оболочка, политика
повторов) покрытие было 6%. Порог не понижен — дописаны тесты: это была
дыра в проверках, а не в процентах.

### Доступность проверяется автоматически

`@axe-core/playwright` на пяти состояниях: список, пустой результат, карточка,
диалог назначения курьера и диалог отмены с ошибкой валидации. Правила —
WCAG 2.0/2.1 уровней A и AA.

Проверка сразу нашла настоящие нарушения контраста: `--color-muted` давал
4.13:1 на самом тёмном из фонов при требуемых 4.5, а `--color-faint` — 2.27:1.
Цвета подобраны расчётом коэффициента контраста для всех трёх фонов, а не
подгонкой на глаз.

### Нагрузочная проверка конкурентности

Скрипт `pnpm --filter @food/api load:courier` доводит N заказов до `preparing`
и одновременно переводит их в `ready`, упираясь в лимит одного курьера.
Результат на 200 параллельных запросах: применено ровно 3, задержка
p50/p95 — 73/121 мс, лимит не нарушен.

k6 намеренно не используется: он требует установки отдельного бинарника,
а проверяемое здесь свойство — корректность блокировки под конкуренцией,
а не профиль пропускной способности. Для полноценного нагрузочного профиля
k6 был бы уместнее.

### Образ API уменьшен вдвое

`pnpm deploy --legacy --prod` собирает каталог только с production-зависимостями
и собранным кодом: **467 МБ → 289 МБ**. Флаг `--legacy` обязателен —
без него pnpm требует `inject-workspace-packages`, а это меняет связывание
пакетов и в разработке: рабочие копии перестают подхватываться без переустановки.

Веб-контейнер получил healthcheck: без него `depends_on: condition:
service_healthy` для него не работает, и оркестратор считает контейнер
готовым сразу после старта.
