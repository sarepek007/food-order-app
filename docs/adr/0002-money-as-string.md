# ADR 0002. Деньги передаются строкой

**Статус:** принято · M1

## Контекст

`total_amount` хранится в Postgres как `numeric(12,2)`. Драйвер `pg` возвращает
`numeric` строкой именно потому, что тип не помещается в IEEE-754 double без потерь.

## Решение

В API сумма — строка, валидируемая регулярным выражением `^\d{1,10}(\.\d{1,2})?$`.
Клиент форматирует её через `Intl.NumberFormat`, но не выполняет арифметику.

## Следствия

* Нет молчаливой потери копеек при сериализации.
* Фильтры `minAmount`/`maxAmount` принимают числа — там точность не критична,
  сравнение выполняет Postgres.
* Плата: сортировку по сумме нельзя делать на клиенте лексикографически,
  она выполняется в SQL.
